# 处理申请

侧边栏的 **申请人追踪**。
谁被交给了哪一份表单，以及每一个人进行到哪里。

![追踪页面](pending:poster-applications-desktop-light "追踪表格，筛选到某一个职位。")

**答案不在这里。** 别人在表单上写的内容在 Google 试算表里。
每一行都用 **回复** 链到那则职位的回复表格。
这一页追踪的是交接和状态。

## 九个状态

它们按流程顺序排列，但没有任何东西强迫您照顺序走。

| 状态 | 意思 |
|---|---|
| 已开始 | 他们打开了表单。此外一无所知。 |
| 已申请 | 他们提交了，可能是已确认，也可能是自行申报。 |
| 审阅中 | 有人正在看它。 |
| 已入围 | 在您正在考虑的那一组里。 |
| 面谈中 | 正在和他们谈。 |
| 已发出邀约 | 您已经把职位提供给他们。 |
| 已录取 | 他们拿到了。 |
| 这次不合适 | 不再往下走。 |
| 已撤回 | 他们自己退出了。 |

**已开始和已申请是网站设定的**，不是您。已撤回是申请人自己的。
中间那五个是您的。

某一行旁边的 **未确认**，代表没有人告诉我们表单已经提交。
那不是对那个人的评价。请看[开启已确认提交](/staff/poster/confirmed-submissions)。

## 找出记录

可以按职位、按状态、按日期区间，以及按申请人筛选。
概览上的流程分组点进来时，这一页已经筛选好了。

**导出 CSV** 会给您屏幕上的内容，连同筛选条件，方便开会或做试算表。

## 一行的详细内容

**详情** 会打开那份申请：是谁、哪个职位、什么时候开始、什么时候申请，以及下面所有内容。

![一份申请](pending:poster-application-detail-desktop-light "详情视图，包含状态控件、备注、待办事项和历史记录。")

**状态。** 更改后保存。每一次更改都会被记录。

**备注。** 只有员工看得到，申请人永远看不到。
请写下某人为什么被移动，因为三个月后读它的人可能不是您。

**历史记录。** 每一次移动、是谁做的，以及来自哪里：
员工、申请人、表单，或自动。
当有人问起发生了什么事时，这就是那份记录。

**待办事项。** 就这个职位向这个人提出的所有问题，以及他们的回复。
请看[索取更多资料](/staff/poster/asking-for-more-information)。

## 一次更改多笔

勾选那些行，选一个状态，然后套用。
这和一笔一笔改是同一种更改。

批量处理适合一批「审阅中」。
批量婉拒之前请先想一想：收到的每一个人看到的讯息都是同一则。

## 录取与婉拒

这两个和其他状态不同，因为申请人会被告知。

选 **录取** 或 **这次不合适**，然后写讯息。这里刻意没有范本。

- **主旨** 是必填的。预设是「您获得这个职位」或「关于您的申请」。
- **讯息** 会落在他们的待办事项里，如果他们绑定了 Telegram，也会到那里。
- 撰写视图会在您送出之前，说明这会送达多少人。

> [!TIP]
> 婉拒信是本站最值得好好写的一则讯息。
> 请像一个人那样写，不要像一份表格。
> 等待期结束之后，他们可以再申请。

**录取会让那个职位对那位申请人永久关闭。**
它不会关闭职位，也不会改变名额数字。请在您准备好的时候自行处理。

## 等待期

申请过某个职位的人，在设定的天数内无法再申请同一个职位。
那一行会显示他们正在等待的期间。

**录取和婉拒都不会碰它。** 他们本来在等什么，就继续等什么。婉拒不等于豁免。

详情视图上的 **豁免等待期** 可以让那个人马上再申请那个职位。
当他们是误按申请，或您请他们重做某样东西时，就用它。

更改状态永远不会豁免任何东西。
只有三件事会移动那些日期：一次已确认的申请、一次撤回，以及这个豁免。

## 您在这里不能做什么

**删除记录。** 那是管理员的，它不会出现在您的视图里。

**打开那一行背后的账户。** 申请人账户只有管理员看得到。
这一页是您和申请人打交道的地方。
