# 职位的生命周期

一则职位处于四种状态之一，一个操作让它在这些状态之间移动。
职位列表会显示状态，也提供这些操作。

![职位列表](pending:poster-jobs-list-desktop-light "职位列表，包含状态、语言和截止日期几栏。")

## 四种状态

| 状态 | 在职位板上 | 可以申请 |
|---|---|---|
| 草稿 | 否 | 否 |
| 已发布 | 是 | 是 |
| 已关闭 | 可阅读，不列出 | 否 |
| 已归档 | 否 | 否 |

**草稿。** 写好了但还没发出去，只有员工看得到。每一则职位都从这里开始。

**已发布。** 上线中。它在职位板上、在搜索里、在数据源里，也在网站地图里。

**已关闭。** 在它自己的地址上仍然可以阅读，
所以别人分享出去的链接仍然有效，申请人也能重读自己申请过的内容。
它离开了职位板，申请按钮也不见了。

**已归档。** 完全离开职位板。附在它上面的一切都保留着。

## 绝不用删除来下架一则职位

关闭会让它仍然可以阅读。归档会让它离开职位板。
两者都保留每一份申请、每一则备注，以及附在它上面的每一个数字。

删除是永久的，那是管理员的操作，而且会连申请一起带走。
几乎总有更好的做法。请看本页底部的警告。

## 发布

除非职位有标题、至少一个标签，以及一份申请表单，
否则 **发布** 会被拒绝，并附上理由。

**下架** 会把它退回草稿。
当您要好好修改某个东西时请用它，不要在别人眼皮底下编辑一则上线中的职位。

职位第一次发出去的日期会保留，下架再重新发布不会改变它。
职位板按那个日期排序。
一个已经开放一个月的职位，不该因为有人改了一个错字就跳到最上面。

## 关闭

有两种发生方式。

**手动**，用 **关闭**，随时都可以。

**按它的截止日期。** 隔夜的排程会关闭任何过期的职位。
那是每天一次，所以一则职位可能在过了午夜一两个小时后仍然开着。这没有问题。

没有截止日期的职位永远不会被自动关闭。
它会一直开着，直到有人关闭为止，职位板上会写 **招满为止**。

**录取某人不会关闭职位**，也不会让名额数字减少。
这两件事都由您在准备好的时候自行处理。

## 复制

**复制** 是重新开一次同一个职位的方式。
它会做出一份叫「(copy)」的 **草稿** 副本，带着：

- 每一个栏位、每一个额外区块，以及每一种语言的翻译。
- 那些标签。
- 申请表单地址、预填对照表，以及回复表格。
- 向申请者提出的那些问题。

它不会带走原职位生命历程里的任何东西：
不带发出去的日期、不带它的表单检查结果，也不带它的任何一份申请。
那些属于当初实际刊登过的那个职位。

**表单地址是刻意带过来的。**
重贴通常就是同一个职位再来一次。
每次都要有人把表单地址重新贴一遍，那种摩擦最后会让人干脆去改原来那一则。

复制出来的职位在发布之前有两件事要检查：

1. **截止日期**，通常还是旧的，而且已经过去了。
2. **表单**，如果旧的已经关闭，或者您想让回复分开存放。

## 重贴与等待期

申请过原职位的人 **可以马上申请这份副本**。
副本是一则新的职位，而等待期是按职位算的。

那通常正是您想要的。如果不是，请在职位里说明。

## 删除，以及为什么要三思

> [!DANGER]
> 删除一则职位是永久的，会连它的申请、历史记录、评分和分析数据一起带走。
> 归档会保留全部内容，同时把职位从职位板上拿下来。

删除是管理员的操作，它不会出现在您的列表里。
它会要求密码，并在动手之前显示会被销毁的东西。

几乎每一次，归档才是正确的答案。
