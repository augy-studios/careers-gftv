# 看懂分析数据

侧边栏的 **分析**。每一则职位的表现如何：
谁打开了它、谁按了申请，以及其中有多少人告诉我们他们真的申请了。

![分析表格](pending:poster-analytics-desktop-light "分析表格，按申请点击数排序。")

## 各栏的意思

| 栏 | 计算什么 |
|---|---|
| 打开次数 | 职位页面被打开的次数 |
| 申请点击 | 有人按下申请的次数 |
| 告诉我们是 | 被记录为已提交的申请 |
| 转换率 | 告诉我们是的数量，占申请点击的比例 |
| 评分 | 申请人对这则职位信息的看法 |

任何一栏都可以排序，两个方向都行。

## 转换率是一个下限

> [!NOTE]
> 只有在有人告诉我们之后，一次点击才算作已申请。
> 我们不会追着人要答案，所以转换率是真实情况的下限，绝不是对它的估计。

有三种情况会让一次点击没有得到「是」，其中只有一种是问题：

- **告诉我们否。** 他们看了表单，但没有申请。
- **从未回答。** 他们从那之后就没有再回到网站。
- **超时。** 那个问题一直没有回答，久到隔夜的排程放弃了它。

后两种是沉默，而沉默不是否。
在设置了已确认提交的职位上，大部分沉默都会消失，因为表单会自己汇报。

## 每一个「是」来自哪里

详情视图把它们分成三类：

- **由表单本身确认。** 最可靠的一种，也是已确认提交为您换来的东西。
- **申请人告诉我们的。** 他们在下次来访时回答了那个问题。
- **由员工记录的。** 管理员把一笔未匹配的提交对应到了某个账户。

如果一则职位的「是」全部都是自行申报的，那就该好好设置它。
请看[开启已确认提交](/staff/poster/confirmed-submissions)。

## 检查表单

有些行会带着 **检查表单** 的标记。
当至少五个人按了申请、而其中说自己申请了的不到五分之一时，它就会出现。

**那通常代表申请表单坏了或关了，不是职位写得不好。**
请自己打开那份表单，试着提交一次。

这两个数字都刻意设得宽松。
一次误报的代价是您多看一次结果没问题的表单，
漏掉一次的代价则是每一个尝试过的申请人。

## 评分

申请人可以在申请时为一则职位信息评分。
那评的是这则信息，不是这个职位，也不是您。

**从三个评分起才会显示平均值。**
低于三个时只显示数量，免得一个人的意见读起来像一个定论。

评分是用来找出让人看不明白的职位信息。
分数低通常代表职位描述和表单在某件事上说法不一致。

## 那张图表

打开一则职位，可以看到过去 90 天的打开次数、申请点击和「是」的数量，
另附一张表格列出有事情发生的那些日子。

一天从午夜到午夜，用的是这些时间储存时所在的时区，图表下方会说明。

一则已发布、截止日期还很远的职位如果图表很安静，通常代表没有人找到它。
在成为其他任何问题之前，那首先是标签和标题的问题。

## 分析不会显示什么

**是谁。** 这一页上任何地方都没有名字。人在追踪页面上。

**他们写了什么。** 那在回复表格里。

**未匹配提交**，它们在这一页底部给管理员看，不在您这一份视图里。
