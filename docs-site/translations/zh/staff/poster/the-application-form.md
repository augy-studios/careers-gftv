# 连接 Google 表单

**申请本身是一份 Google 表单。** 本站不收集申请。
它把人交给一份表单，并记录自己这么做过。

没有表单就无法发布职位。

![编辑器上的表单栏位](pending:poster-form-fields-desktop-light "申请表单、回复表格，以及预填栏位。")

## 先建立表单

请复制范本表单。即使您从来不打算开启已确认提交，这也值得做，
因为范本里已经带了那个功能需要的脚本。

表单上有两个设置对我们很重要：

1. **收集电邮地址**，要开启。做不到的话，就加一个标题正好是 `Email` 的问题。
2. **接受回复**，保持开启。停止接受回复的表单是死胡同，隔夜检查会标记它。

如果表单上任何地方都没有电邮地址，提交的内容就永远无法对应到提交它的账户。

## 请贴长网址，不要贴短网址

**申请表单** 这一栏填表单的地址。请用地址栏里的长网址，长得像这样：

```text
https://docs.google.com/forms/d/e/FORM_ID/viewform
```

不要用 `forms.gle/abc123`。短链接对人来说没问题，
却会默默丢掉预填对照表加上去的所有内容。
在涉及预填时，编辑器会拒绝短链接，而且有人申请时代码会再检查一次。

## 预填对照表

选填，值得花那十分钟。
它会把申请人自己的资料填进表单，让他们只打一次而不是两次。

它写成一小段 JSON：

```json
{
  "entry.1234567890": "email",
  "entry.9876543210": "display_name"
}
```

**键** 是表单问题的 entry 编号。**值** 只能是本站会填入的四样东西之一：

| 值 | 填入什么 |
|---|---|
| `email` | 他们账户上的电邮地址 |
| `display_name` | 他们的显示名称 |
| `username` | 他们的用户名 |
| `phone` | 他们的电话号码，如果他们填了 |

值里写其他任何内容都会被忽略。
这是刻意的：对照表指明哪些东西可以被填入，
所以打错的栏位名称会什么都不填，而不是泄漏什么。

### 找出 entry 编号

在表单里使用 **取得预先填入的链接**，随便回答那些问题，然后按到底取得链接。
链接里每一个问题都会有 `entry.1234567890=whatever`。那些数字就是编号。

### 关于预填要知道的两件事

- **您填进去的内容申请人都可以改。**
  所以回复里的电邮地址是他们打的，不能作为他们身份的证明。
- **他们没有设定的栏位不会填入任何东西**，表单打开时那个问题是空的。
  电话号码是选填的，所以这很正常。

如果对照表指的东西都不能用，那就打开一份普通的表单。什么都不会坏掉。

## 回复表格

**回复表格** 是表单写入的那份 Google 试算表。
它只有员工看得到，绝不会出现在读者看到的任何东西里。

请务必填写。它是追踪页面上的一行通往那个人实际写了什么的链接。
没有它，就得有人到 Drive 里去翻找。

## 有人申请时会发生什么

1. 他们在职位上按 **申请**。
2. 网站记录这次交接发生了，并在新标签页打开预填好的表单。
3. 他们填好表单并提交给 Google。
4. **网站不会被告知**，除非设置了已确认提交。
   他们下次来访时，网站会问他们有没有申请。

第 4 步是值得修好的一步。
请看[开启已确认提交](/staff/poster/confirmed-submissions)。

## 当表单出问题时

隔夜的排程会检查每一则已发布职位的表单，并在概览上汇报。它可能说两件事：

- **表单不接受回复。** 有人在 Google 那边把它关了。
- **表单不存在。** 被删除了，或者共享设置改了。

不论哪一种，每一个在那个职位上按申请的人都会走进死胡同。
请修好表单，或把职位下架。

不要换上一份新表单，却让职位带着坏掉的旧表单继续发布着。
分析页面会标记点击数高但申请数很少的情况，而那通常就是这个原因。
