# 3. 设计

- 严格照 `gftv-theme.md` 来。那就是 Proxima Nova，国际兽视的品牌字体，自行托管在 `assets/fonts/` 下。然后是 `.glass-card` 这个基础样式，以及 `--brand`、`--brand-dark`、`--surface` 和 `--text` 这几个变量，颜色是国际兽视的蓝灰、Hello 黄，链接用国际兽视红。链接在任何状态下都不加下划线。正文里的链接比周围的文字重一档字重，靠的就是这一点来辨认。
- 双轴主题切换器（配色主题加上浅色/深色模式），在 `<html>` 上用 `data-color-theme` 和 `data-mode`，和其他国际兽视应用一样。浅色是默认，并且不理会系统偏好。
- 不用渐变、不用光球、不用色块。图标用内嵌 SVG，绝不用表情符号。文案里不用破折号。
- 在每一种主题和模式的组合下，所有文字和正文都要达到 WCAG AA 的对比度。
- **任何要等的东西都要显示它正在等。**绝不要一个卡住的画面，也绝不要一个光秃秃的空容器。用 `gftv-theme.md` 里的加载基础样式。结果还没有形状时用转圈，形状已知时用骨架屏。两者都带 250 毫秒的延迟，这样一个很快的回应根本不会被看到在加载。每一个指示器都要配上屏幕阅读器念得出来的文字，因为动画什么都念不出来。这一条适用于搜索结果、职位加载、申请交接，以及每一张管理后台的表格。
- 移动优先，而不是先做桌面再补一个手机版。依第 16 节，平台和说明文件网站在小屏幕上都必须完全可用。第 12 阶段会检查这一点，所以绝不是靠假设。

## 3a. 语言：英文、华文，以及之后会来的

这个平台有英文和华文两种语言。一次只显示一种语言。这不是一个基本上是英文的网站上做了一部分翻译。每一个职位、每一条界面文字、每一个静态页面，还有管理后台，两种语言都有。

**这里的中国话是新加坡华文**，也就是「华文」，不是大陆的普通话。国际兽视是一个新加坡的组织，文案读起来应该像是在那里写的。那更多是用词的问题，而不是语法的问题，而且差别是真实存在的：

| 用 | 不用 | 意思 |
|---|---|---|
| 义工 | 志愿者 | 义工，也是最显眼的那个标记 |
| 华文 | 中文, 简体中文 | 指这种书面语言的时候 |
| 电邮 | 电子邮件 | 电邮 |
| 营运 | 运营 | 营运 |
| 摄影棚 | 录影棚 | 摄影棚 |
| 文件 | 文档 | 纸本意义上的文件 |
| 合约 | 合同 | 合约。从第 12 阶段起就在 `gen-review.js` 里，2026 年 9 月 11 日发现两份清单不一致时加到这里 |

在切换器里，这种语言自称「华文」。文件标记为 `zh-Hans-SG` 而不是 `zh-Hans`，因为文案实际上就是那样。前缀匹配意味着任何以 `zh` 或 `zh-Hans` 为键的东西仍然适用。字体栈只列简体字形：繁体字形在两套写法不同的地方会渲染出错误的字形。

新增文案时，拿它对照那张表。拿不准的时候，判断标准是它在《海峡时报》上读起来自不自然，而不是在一份北京的报纸上。

**切换器。**头部的一个语言控件，运作方式和主题切换器完全一样，就摆在它旁边。它是自己独立的一个按钮，带一个地球图标，绝不是主题弹窗里的一个分区。一个只读华文、又落在英文站上的读者，不能指望他找得到一个写着 “Theme” 的控件。一个地球图标不用读字就看得懂。每一种语言都用它自己的文字自称，`English` 和 `华文`，两者都绝不翻译。所以不论界面当前是哪一种语言，这两个选项读起来都一样。

**存储。**这个选择存在 `localStorage` 里的 `gftv-careers.locale`，和那两个主题的键放在一起，别的地方都不存。每一个 `<head>` 里都有一段在首次绘制前运行的脚本，在 `<html>` 上设好 `lang` 和 `data-locale`，就在设那两个主题属性的同一段里。

**语言刻意不放进网址。**由此带来三个后果，而它们是接受下来的，不去绕开：

- 一个华文读者分享出去的链接，会以接收者自己存着的那种语言打开。
- 搜索引擎永远只看得到一个页面的英文版。所以第 4 节里的 `sitemap.xml`、canonical 标签和 `JobPosting` JSON-LD 都只描述英文的那个职位。华文的职位没办法透过华文搜索被找到，Google Jobs 上带的也会是英文。
- `hreflang` 发不出来，因为根本没有第二个网址可以指。

如果这当中有哪一点变成了问题，解法是在已存的偏好之外再带一个 `?lang=` 参数。那是加上去的，不用改数据库结构。

**界面文字。**放在 `main-site/assets/i18n/en.json` 和 `zh.json` 里，用扁平的点号键，透过 `data-i18n`、`data-i18n-html` 和 `data-i18n-attr` 属性套用。英文永远作为兜底那一层加载。所以华文文件里缺掉的键会渲染成英文，绝不会是一个空元素或者一个原始的键名。英文文字留在标记里作为元素自己的内容，所以在没有 JavaScript 时、以及在词典还没解析出来之前，页面读起来都是对的。

**内容。**默认语言的内容放在基准行上，其他每一种语言都是翻译表里以语言为键的一行。正是这个结构，让加马来文或淡米尔文只花 `gftvjobs_locales` 里的一行和一个词典文件，绝不用一次迁移。每种语言每个字段各开一列的做法，每次都会多出十个列和一整套新的约束。一份翻译只有在它的 `is_ready` 标志被设了之后才会显示。这样一份草稿或者还没校过的翻译，就可以留在表里而不上线。任何留空的字段都退回用基准行。一个职位可以完全没有翻译就发布，那时它以默认语言呈现，并附上一句说明。但一份被标记为可发布的翻译，必须带上那种语言的名称、摘要和描述。一个翻好的标题压着一段没翻的正文，比干脆没翻还糟。标签和部门的 slug **不**翻译。它们是网址标识符，也是筛选值，一翻译，别人一切换语言，每一个分享出去的链接就都断了。

**搜索。**不同语言的搜索方式不一样，取决于 Postgres 分不分得了它的词，而且非这样不可。Postgres 分不了汉字。所以 `to_tsvector` 会把一串汉字当成一个词，而搜一个词的一部分永远匹配不上。`zhparser` 和 `pg_jieba` 能解决这件事，但 Supabase 上没有。所以英文仍然用加权的 `tsvector`，以 `ts_rank_cd` 排序，用 `ts_headline` 高亮。Postgres 分不了词的语言，则用 `pg_trgm` 去匹配它翻译行上那个生成的 `search_text` 列。那是按名称的接近程度排序的，没有高亮片段。两种都能用，但只有英文排得好。要在管理说明文件里讲清楚，而不是让管理员以为华文搜索坏了。

**排版。**Proxima Nova 没有中日韩字形，所以汉字会落到读者自己的系统字体上。在苹果平台上是 PingFang SC，在 Windows 上是微软雅黑，在 Android 和 Linux 上是 Noto Sans CJK SC。字体栈里刻意不点名任何中日韩字体。各平台的默认本来就是对的字体。点名它们，反而会盖掉一个已经在自己设置里选了别的华文字体的读者。让这件事正确的是 `lang` 属性，而不是字体栈。汉字是中文和日文共用的，而一个没有语言可依据的浏览器，可能会用日文字体来渲染中文。有不少共用的字在那里写法是不一样的。每个页面都在首次绘制前从存着的语言设好 `lang`。万一哪天这件事不做了，华文就会以错误的字形渲染，而别的地方看起来一切正常。华文的文档还会得到稍微松一点的行高，作用范围是 `[data-locale="zh"]`，因为拉丁文案想要的那个行距，对汉字来说读起来太挤。

**名称。**GFTV 在华文里是**国际兽视**，这个平台是**国际兽视入队平台**，字面意思就是加入团队的平台。凡是在读华文的地方都用这两个，不要用英文的写法。**这个华文名字不是 “Careers” 的翻译，而且刻意不是。**“Careers” 暗示有薪水，正因如此每一个职位都得说明它是无薪的，而「招聘」会把那个暗示带进华文里。「入队」说的才是实际提供的东西。拉丁字母和汉字之间要有一个空格，汉字和汉字之间绝不要。所以是 `Telegram 账户` 和 `关于国际兽视入队平台`，一串汉字里面不留空格。

**哪些不翻译。**如上，标签和部门的 slug，因为它们是网址标识符。还有 `<noscript>` 的内容，因为 JavaScript 一启用就读不到它了。

这一段原本说，说明文件网站员工那一半保持英文。它要求在那一半的顶上放一句说明。**2026 年 9 月 3 日，16f 推翻了那个说法，并由第 14 阶段第 9 部分做了出来**，把全部八十二页都翻译了。整个说明文件网站都翻译了，包括员工那一半。这里做出更正，是为了让 3a 和 16f 不会互相矛盾。依第 4 节和职位发布者指南，职位上那句链接卡片的文字，不论分享到哪里都保持英文。抓取链接卡片的那个东西，没有任何语言可以提供。

## 响应式要求

`main-site` 和 `docs-site` 一体适用。

- 断点：640px 以下是单列布局，640 到 1024px 之间是宽松的双列布局，1024px 以上是完整布局。先做小屏幕再往上加列，因为反过来往下改才是横向滚动的来源。
- **两个网站都用汉堡导航。**平台把头部导航和管理侧栏收进一个菜单按钮后面。说明文件网站把左侧栏收进一个按钮后面，并把右侧的页内目录收成内容上方一个可折叠的区块。两边的按钮行为和动画都一样，这样它们感觉像同一个产品。
- 每一个抽屉面板都从左边打开，打开时把焦点锁在里面。它在按 Escape 时、点背景时，以及导航到新页面时关闭。它有一个明显的关闭控件，而且用键盘到得了。在触发按钮上设 `aria-expanded`，在面板上设 `aria-hidden`，并在它打开时锁住页面滚动。
- 管理后台也不例外。640px 以下表格重排成堆叠的卡片，而不是横向滚动。批量选择仍然够得到，而任何埋在宽表格某一行里的操作都要浮到卡片上来。一位管理员在展会上用手机看申请，在这里是常态，不是边缘情况。
- `/search` 的筛选面板在小屏幕上变成一个底部弹层。打开它的那个按钮带着当前生效的筛选数量，而一个“套用”的动作把它关掉。
- 触控目标至少 44 乘 44 个 CSS 像素，彼此之间要有真正的间距。任何东西都不依赖悬停，而任何靠悬停才出现的东西都要有一个点按的等价做法。
- 一直到 320px 宽都不能有横向滚动。长词、uuid 和标签名要换行，或者截断并配一个 title 属性，而不是把布局撑开。
- 弹窗，包括 7c 的交接弹窗，在小屏幕上变成满宽的弹层，按钮放在拇指够得到的地方。在有刘海的手机上要尊重安全区域的内缩。
- 表单用恰当的 `inputmode` 和 `autocomplete` 值，输入框至少 16px，这样 iOS 在聚焦时不会放大。
- 在 320、375、414、768、1024 和 1440 上测试。两种方向、两种主题，以及浅色和深色模式都要看。

## 3b. 两个网站都用平实的语言

2026 年 9 月 3 日加的。**两个网站上的每一个字，都是写给一个没有技术知识、想找一个职位并且去申请的人看的。**那个读者就是标准，英文和「华文」 一样。它适用于平台、说明文件网站、`/status` 上的阶段列表，以及机器人自己的消息。

具体来说是这样：

- **一句话一个意思，而且没有一句超过 25 个词。**这个上限不是目标：平台自己的平均值不到七个词。它是用来抓那种因为写的人太小心、于是长出了三个从句的句子，而这里的文案要坏也是坏在这上面。
- **用日常的词。**用“用完”，不用“耗尽”。用“登录”，不用“认证”。一个更短的词若意思一样，那就用那个词。
- **点出那个术语，然后解释它。**Passkey、救援码、两步验证、冷却期：把那个词留着。它就是按钮上和浏览器自己的提示里用的那个词。在读者第一次遇到它的地方给它一句平实的解释。换掉那个词，只会让页面和屏幕上说的不是同一件事。
- **理由仍然要跟着规则走。**平实不等于单薄：这个网站会告诉别人一件事为什么是这样运作的，而这一点保留下来。只是用更短的句子说。
- **这里的中国话是新加坡华文**，依 3a，而那里那张用词表是规则，不是偏好。

`node check-copy.js` 强制执行这里面脚本看得见的那三项：被禁的措辞、25 个词的上限，以及 3a 那张用词表。其余的都是判断，所以才写在这里。
