# 14. 离线行为

这个网站必须是一个可以完整安装、断网也还有用的 PWA。要老实讲清楚界线：浏览、阅读和评分离线可用，而任何牵涉到账户或 Google 表单的功能都需要网络。做不到的部分不要假装。

### 离线可用

- 完整的应用外壳：首页、`/search`、职位详情、账户页面、样式、字体、图标，以及离线备用页。
- 每一个已经打开过的职位，都能从缓存里完整读到，不论有没有登录。
- 最近一次成功的 `/search` 结果，连同它的筛选条件和标签，这样职位板仍然可以浏览。要标上它是什么时候缓存的。
- 收藏的职位、我的申请，以及待办事项列表，都来自申请人自己数据的本地副本。回复一个事项和其他操作一样进队列。
- 交接弹窗里的星级评分和是或否的回答，先在本地排队，等网络回来再发出去。

### 需要网络，而且明说

- 登录、注册和两步验证。在那些表单上显示清楚的离线状态，而不是让提交默默失败。
- 打开 Google 表单，所以离线时申请按钮是禁用的，并写明原因。
- 管理后台。只缓存它的外壳，并显示离线提示，而不是过期的管理数据。绝不让管理员对着一份缓存的申请列表做操作。
- 任何会显示到别人数据的地方。

### 缓存策略

- 安装时预缓存外壳和静态资源，以 `sw.js` 顶部的一个构建版本常量为键。**网站每有一次改动就要把它加一。**不是一个阶段一次，也不是只有 `sw.js` 自己改了才加，否则回访的人拿到的还是上一版。
- **两份** `assets/i18n` 词典都要预缓存，不只是当前那一份。它们很小，而离线时切换语言的申请人不该看到一个没翻译的页面。
- 一个缓存下来的职位要两种语言都缓存，因为接口一次只返回一种语言。要么把两次回应都缓存，要么把职位缓存成同时带两种语言的一份；不要让离线切换语言把页面变空。
- 静态资源：缓存优先。
- 公开的职位数据，也就是列表、职位、部门和标签：先给缓存再后台更新。立刻拿缓存的那份出来，在后台刷新，数据变了就更新画面。
- 需要登录的接口、会话，以及 `api/admin` 下的一切：只走网络。绝不把需要登录才拿得到的回应放进 Cache API。缓存是按来源共用的，而这是一个有两套账户体系的平台，域名上还挂着其他国际兽视的应用。
- 申请人自己的数据改放在 IndexedDB，存在一个以他们的用户 id 为键的库里，登出时整个清掉。登录时，如果存着的用户 id 和正在登录的这个不同，先把数据库清空再写任何东西。
- 把缓存的职位数量限制在一个合理的数目，大约 100 个，并优先淘汰最久没看的。
- 在 `vercel.json` 里用 `Cache-Control: no-cache` 提供 `sw.js`，否则一个过期的 service worker 会把旧版本无限期钉住。

### 排队的操作

- 离线时把弹窗的评分和它是或否的回答排进 IndexedDB，连同分析记录的 id、想要写入的值，和一个时间戳。
- 在支持的地方用 Background Sync API 把队列发出去。其他地方就在下一次有网络的页面加载时发出去，因为 Safari 不支持 Background Sync。
- 让每一个排队的操作都是幂等的，这样重发不会重复计数。服务器本来就以分析记录的 id 为键，所以重复的回答是覆盖，不会叠加。
- 一个排队中的回答在服务器确认之前仍然算是待回答。不要凭本地的一条队列记录就开始算重新申请的冷却期。
- 在界面上把排队中的项目显示成等待同步，绝不显示成已完成。等服务器的回应到了再对齐。

### 界面

- 网络断掉时显示一条一直在、但不碍事的离线横幅，用 `navigator.onLine` 加上 `online` 和 `offline` 监听。网络一回来就把它移掉。
- 任何缓存的画面都带一个不显眼的“最后更新”时间，免得有人把旧的职位板当成当前的。
- 离线做不到的控件要禁用，并把原因写在控件本身上，绝不留一个点了就失败的死按钮。
- 为没有缓存过的地址准备一个离线备用页，把缓存的职位和收藏的职位提供出来当作去处。
- 有新的 service worker 在等着时给出更新提示，让申请人自己重新加载。绝不在他们脚下把页面换掉。`skipWaiting` 和 `clients.claim` 只在那个提示之后才用。

### Manifest 与安装

- `manifest.json`，带国际兽视入队平台的全名和简称，显示模式为 `standalone`。它带上 `gftv-theme.md` 里的国际兽视主题色和背景色、192 和 512 的可裁切图标，以及 `/` 的 `start_url`。
- 加 `/search` 作为一个快捷方式，`/account/tasks` 作为第二个。
- 在 Chrome 和 Android 上测试可安装性和各条离线路径。在 iOS Safari 上确认离线备用页可用，那里的 service worker 支持是真的，但比较严格。
