# 4. 公开网站（无需登录）

**首页（`/`）**
给一般公众看的落地页。分区如下：
- 主视觉区，带国际兽视入队平台的名字和一句关于加入国际兽视的短句。它带一个职位搜索框，关键词加上一个类别或部门下拉，提交到 `/search`。
- 精选或最新职位：一小格从接口实时拉来的职位卡片，配一个通往 `/search` 的“查看全部职位”链接。
- 一个“为什么来国际兽视做义工”那类的分区，放几张价值主张卡片。
- 按部门或组别浏览。
- 申请流程是怎么走的，用带编号的步骤写出来。
- 页脚，与其他国际兽视网站保持一致。

**职位列表与搜索（`/search`）**

浏览界面只有一个，不是两个。`/search` 既是完整的职位列表，也是搜索结果页。没有任何查询参数时，它显示每一个已发布的职位，最新的在前。带 `q` 参数或者用了任何筛选时，它显示匹配的那一部分。同一个页面、同一批组件、同一个网址，所以分享出去的链接总是完整重现分享者当时看到的东西。

- `/jobs` 后面没有 id 时，301 跳转到 `/search`。`/jobs/` 下面唯一存在的东西就是单个职位。
- 首页主视觉区的搜索框提交到 `/search?q=...`。
- 关键词搜索由 Postgres 全文搜索支撑。查询范围涵盖职位名称、摘要、描述、职责、要求、部门名称和标签名称，其中名称和标签的权重最高。
- 筛选项：部门、标签、投入方式、地点或远程、职位状态。排序方式为最新、截止日期或相关度，其中有 `q` 时相关度是默认，没有 `q` 时最新是默认。按截止日期排序时，用 `order by closes_at asc nulls last`，这样没有截止日期的职位排在最后而不是最前。
- 标签筛选：一片标签云或者一行标签，可以同时选多个。多个标签之间默认取“或”，另配一个“全部符合”的开关来取“与”。在每个标签旁边显示数量，并隐藏没有任何已发布职位的标签。
- 结果上方放快捷筛选标签：“今天发布”、“本周发布”、“即将截止”和“不设截止”，每一个都带实时数量。“即将截止”只匹配 `closes_at` 在未来 14 天之内的职位，绝不把不设截止的算进去。它们和完整的筛选面板并排，而不是放在面板里面，这样常用的几种情况都只要点一下。
- 边打字边给的联想，来自一个轻量的接口：匹配的职位名称、匹配的标签和匹配的部门，分成那三组显示。防抖大约 250 毫秒，最少两个字符，并且要能完全用方向键和回车键操作。
- 有 `q` 时按相关度排序，并用 `ts_headline` 在摘要片段里高亮匹配到的词。
- 用三元组相似度做兜底来处理拼错和差一点的情况，也就是全文搜索什么都搜不到的时候。显示一个“找不到 X，你是不是要找 Y”的状态，并把最热门的标签放上去当作回到正轨的入口。
- 最近搜索存在 localStorage 里，在搜索框为空时以标签形式提供。任何与搜索有关的东西都不在服务器端和账户挂钩存起来。
- 服务器端分页。
- 每一项状态，也就是查询词、筛选、排序和页码，都放在网址的查询串里，这样结果可以分享，后退键也表现正常。筛选变动时用 `history.replaceState` 更新它，绝不靠重新加载。
- 每张卡片显示名称、部门、地点、投入方式、发布日期、截止日期，以及最多四个标签。`closes_at` 为空时，在日期的位置显示“招满为止”。绝不要把那一栏留空，也不要印出 “null”。点一个标签是按那个标签筛选，不会打开那个职位。
- 每个职位详情页都输出 schema.org 的 `JobPosting` JSON-LD，这样职位才有资格被 Google Jobs 收录。本站还对外提供一个公开的 `api/public/jobs.json` 数据源，给任何想汇总职位的人用。

**职位详情（`/jobs/{id}`）**
- 一个职位的规范网址是 `/jobs/` 后面接该职位在 Supabase 里那一行的 uuid，例如 `/jobs/3f9a1c2e-8b47-4d10-9a3e-5c61d2f0ab88`。
- **这条路由是服务器端渲染的，不是一个加载后再去取数据的静态页面。**`vercel.json` 把 `/jobs/:id` 重写到一个无服务器函数。那个函数注入 `<title>` 和 meta 描述。它还注入 Open Graph 和 Twitter 卡片标签，以及 `JobPosting` JSON-LD，都在 HTML 发出去之前完成。页面主体仍然可以在客户端补齐。

  原因是链接卡片。Discord、Telegram、Slack 和其他每一个抓卡片的服务，都是取那个网址、读它送过来的标记；它们都不跑 JavaScript。一个加载之后才去取职位的页面，抓出来的卡片就是那个静态外壳上写着的东西。于是全站每一个职位的卡片文字都一模一样、都很笼统。在服务器端渲染这些标签，是让一个职位链接带上自己名称和描述的唯一办法。

  只有这一条路由是这样做的。依第 2 节，平台里其他一切仍然是静态页面加客户端取数据。

**链接卡片**

- 每个职位带一个可选的 `og_description`，是管理员为卡片写的一句短话。它从来都不是必填的。
- 它为空时，退回用该职位 `description` 的第一句。取第一个句子，而不是前 N 个字符，这样卡片永远不会断在词的中间。断句是分语言的：英文看句号，华文看 `。`。用之前先把 markdown 去掉。
- 把渲染出来的值控制在大约 200 个字符。Discord 大约显示 350 个，而多数抓卡片的服务在接近 200 就截断，所以再长的必定会在某处从句子中间被截掉。
- 图片就用本站的卡片图，除非以后某个职位自己设了一张。不要把 Google 表单地址、回复表格地址，或者任何其他非公开的东西放进卡片。卡片是由第三方服务器去抓、并由它缓存起来的。
- **卡片永远是英文的。**爬虫没有 `localStorage`，所以它没有语言偏好可读，而依 3a，语言也是刻意不放进网址的。分语言的卡片文字是存在翻译记录上的。万一以后加了 `?lang=` 参数，它已经准备好了，而今天没有任何东西会拿它出来用。要在管理后台的说明文字里讲清楚，否则会有管理员写了一句华文的卡片文字，然后纳闷为什么没人看得到。
- `/jobs` 后面没有 id 时跳转到 `/search`，所以没有别的东西来抢这条路由。详情页只匹配形状像 uuid 的那一段，其他任何不是 uuid 的都当作找不到。
- 保留 `slug` 那一栏。把 `/jobs/{slug}` 作为一个别名提供，301 跳转到 uuid 的网址。这样在这次改动之前分享出去的链接仍然打得开，而且每个职位永远只有一个规范地址。
- 一个不存在的 uuid，或者指向一个 `draft` 职位的 uuid，返回一个正经的 404 页面，绝不返回一个空壳。一个 `closed` 的职位仍然会渲染，只是申请按钮禁用并附上已关闭的提示。依 7g 的可见性规则，一个 `archived` 的职位只对申请过或收藏过它的申请人渲染。对其他所有人它都回 404。
- 把 `<link rel="canonical">` 设成 uuid 的那个网址。
- 靠上的位置放标签，每一个都链到按那个标签筛选过的列表。
- 完整的描述、职责、要求、加分项、投入方式、地点和截止日期；`closes_at` 为空时则写“招满为止，申请随到随看”。
- 一个分享按钮，以及一个“回到结果”的链接，带着先前的查询串回到 `/search`。
- 申请按钮。申请由 Google 表单处理，所以对已登录的申请人，这个按钮启动 7c 的交接。

**未登录的访客看到什么**

- 整个职位都是公开的。名称、摘要、完整描述、职责、要求、投入方式、地点、部门、标签、发布和截止日期，全部都是。没有预告片、没有打码的文字、没有“登录后查看详情”。挡在门后的只有“申请”这个动作本身。
- Google 表单地址是唯一的例外。它绝不能出现在公开的职位数据里、HTML 源码里、JSON-LD 里，或者 `jobs.json` 数据源里。它只由一个需要登录的接口提供，这样未登录的访客没办法把它捞走来绕过这道门。
- 在申请按钮的位置，放一个读起来像是申请动作、而不像一堵墙的控件。类似“申请这个职位”，点了之后打开一个小的登录提示。那个提示用一行说明申请需要一个账户。它给出两个同等的选项，登录和开设账户，另外写一句说注册很快，而且不需要审批。
- 收藏一个职位也照这样处理，其他任何要往账户里写东西的操作也一样。
- 搜索结果页也是完全公开的，连筛选和标签都是。那里没有任何东西需要会话。

**登录之后回来**

- 在登录和注册两条流程里，都把 `?redirect=` 带回那个职位。那也包括注册之后自动登录的那一步，这样新的申请人会回到他们出发的地方，绝不会落在一个空空的账户页上。
- 用一份严格的白名单来校验这个跳转，只允许本来源的相对路径。绝对网址、省略协议的网址，以及任何带主机名的，都要拒绝，否则这个参数就变成一个开放跳转漏洞。
- 回来之后，不要自动启动交接。登录后的跳转背后没有用户的动作，所以新标签页会被拦下来，而弹窗会莫名其妙地冒出来。让他们落在那个职位上，申请按钮已经可用、滚动到可见位置并短暂高亮。再加一行简短的确认，说他们已经登录、可以申请了。下一下点击是他们自己的。
- 在这一来一回之间要保住原本的意图。如果他们点的是收藏而不是申请，回来之后就把收藏完成，并且说一声。

**静态页面**：关于国际兽视入队平台、常见问题、隐私声明、条款。

**发现类文件**

平台这边在第 12 阶段做，说明文件网站那边在第 13 阶段做，都等它们所描述的页面真的存在之后再做。做得更早，只不过是列出一堆占位路由而已。

- **`/sitemap.xml`**，平台这边是生成的，不是手写的，因为职位一直在变。用 `vercel.json` 里重写到那个路径的一个函数来提供它。它列出首页、`/search`、各静态页和 `/status`。它还列出每一个 `published` 职位各自的网址，`lastmod` 取自 `updated_at`。要排除已关闭、草稿和已归档的职位，`/admin`、`/account`、`/login`、`/register` 下面的一切，以及 0c 的每一条占位路由。用 `s-maxage` 缓存它，免得每次请求都重新生成。
- **`/robots.txt`**，平台这边允许各公开页面，禁止 `/admin`、`/account` 和 `/api`，并指向 sitemap。
- **`/llms.txt`**，两个网站都要，照 llmstxt.org 的约定来。它是放在根目录的一个简短 markdown 文件，带着网站名称和一段话的介绍。下面是一份值得读的页面链接清单，按标题分组。平台这边写的是国际兽视入队平台是什么、怎么申请，以及通往 `/search`、说明文件网站和 `jobs.json` 数据源的链接。说明文件网站那边则是每一页指南一个链接，各配一行说明。
- 把 `llms.txt` 限制在公开的、面向申请人的材料上。不放管理说明文件、不放接口路径、不放 Google 表单地址，也不放任何需要登录才能看的东西。把它当作一个公开页面，因为它本来就是。
- 值得知道的是：llmstxt.org 是一个提议中的约定，不是标准，各家的支持也参差不齐。发布它几乎不花什么成本，也可能有用，但不要做任何依赖它会被读取的东西。
- 两个网站也都有 `sitemap.xml` 和 `robots.txt`，说明文件网站那边照第 16 节所写，由它的页面清单生成。
