# 9. API 设计

`main-site/api/` 下的 RESTful 路由，分组如下：

- `api/auth/staff/*`：登录、验证两步验证、登出、会话、受信任设备（列出、撤销、全部撤销）
- `api/auth/applicant/*`：注册、登录、登出、会话、个人资料、修改密码。然后是 forgot-password（验证一个救援码）和 reset-password（用掉那张凭据）。然后是 recovery-codes（生成、查剩余数量）和 trusted-devices（列出、撤销、全部撤销）
- `api/public/*`：职位列表、按 uuid 取职位详情、为跳转做的 slug 转 uuid 查询、部门、标签、搜索、联想
- `api/applications/*`：start、respond、pending、列出我的、撤回。start 会写入分析记录、更新或插入追踪记录，并返回预填好的表单地址和分析记录的 id。respond 记录是或否的回答，回答是则设置冷却期。pending 返回这位申请人所有还没回答的提示。
- `api/saved/*`：收藏、取消收藏、列出我的
- `api/ratings/*`：为一个职位新增或更新评分，来自 7c 的弹窗
- `api/translations/*`：反馈一个问题、列出我自己的反馈
- `api/tasks/*`：列出我的（与待回答的申请提示合并）、取单个、回复、忽略一条通知、给徽章用的未读数量。一次回复除了自由文本之外，还带着该事项各个问题的答案。这个接口会依 7g，拿它们和存在该事项上的问题集比对校验。每一个必答题都必须有答案。每一个单选和多选的答案都必须是该题自己的选项值之一。任何答案都不能指向该事项没有的问题。而且只有它才可以做这件校验。问题是发给浏览器的，不能指望浏览器把答案原样送回来。
- `api/telegram/*`：生成关联令牌、轮询关联状态、解除关联、开关两步验证、索取登录验证码、验证登录验证码、使用一次性链接
- `api/invites/*`：列出我的、标记已看、婉拒
- `api/account/danger/*`：先验证密码，然后才是各个破坏性操作
- `api/webhooks/form-submit`：第 13 节写的 Apps Script 对接
- `api/admin/*`：jobs、applications、analytics、tasks、invites、departments、tags、tag-merge。然后是 users、admins、stats 和 export。然后是 translations，也就是依 8.11 的反馈队列和待翻译清点。然后是 maintenance，依 8.12 读取和切换功能覆盖开关。这里没有 `api/admin/docs`：依 8a，手册已经搬到说明文件网站去了。
- `api/public/feature-status`：维护覆盖开关，任何人都可以读，可以短时间缓存，但不能更久。它只带着哪些已上线的功能目前是关着的，以及每一项对外的说明。阶段列表留在 `build-status.json` 里，不在这里重复一份。这是浏览器需要、而静态文件答不上来的唯一一件事。它是刻意分开的，这样读不到它的时候网站仍然是全部功能开着能用的，而不会一片空白。
  - 依 0c，每一条挡在可切换功能后面的路由，都在服务器端检查同一个覆盖开关，并以维护提示语回 503。这个检查应该放在 `api/_lib/settings.js` 旁边的一个公用函数里，由每条受管的路由调用。这样哪些功能可切换就是一个文件里的一份清单，而不是一种约定。
- `api/auth/staff/*` 同时也承载 5f 的员工账户设置套件。那包括 passkeys（列出、注册、改名、移除）和 authenticator（启用、移除）。然后是 backup-codes（数量、重新生成）和 recovery-codes（数量、重新生成）。然后是 sessions（列出、撤销、全部撤销），以及依 5g 的 forgot-password 和 reset-password。还有危险操作区的各项操作，都挡在它们自己的密码验证步骤后面。

说明文件网站在 `docs-site/api/` 下有自己的一小组路由，跑在它自己的 Vercel 项目上。依 5h，它是各做一份，而不是共用：

- `api/auth/*`：登录、验证两步验证、passkey 的挑战与验证、登出、会话、受信任设备。再加上与上面同一套账户设置套件，好让 5f 能挂在两个网站上。
- `api/content/*`：按键取一个受限页面，以及传送一张受限图片。两者都检查员工会话和该页面所需的角色。对没有权限的调用方，两者都回 404 而绝不回 401，这样任何人来试探都无法确认某个页面存不存在。
- `api/search-index`：搜索索引里受限的那一半，按读者的角色划分。公开的那一半是一个静态文件。

所有路由的共同要求：
- **每一个会返回人看的内容的接口都接受一个语言参数**，`en` 或 `zh`。它就用一般的字段名返回那种语言。它绝不两种都返回、然后让客户端自己挑。没有传语言的调用方拿到英文。客户端每次请求都带上已存的偏好。登录相关的路由，以及只返回 id 和时间戳的接口，都不需要它。
- 校验并清洗每一个输入。只用参数化查询。
- 统一的 JSON 错误结构，配上恰当的状态码。绝不把堆栈信息或数据库错误漏给客户端。
- 对登录、注册、两步验证和申请提交做限流。用一张表或者内存做的简单限流器就行，在 README 里写明你选了哪一种。
- 登录失败时给笼统的错误文案，这样回应不会透露某个用户名存不存在。
