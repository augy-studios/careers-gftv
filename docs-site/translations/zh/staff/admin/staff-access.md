# 管理员工权限

侧边栏的 **员工权限**。谁可以打开这个管理后台，以及本站就他们所做的那一个决定。

![员工权限列表](pending:admin-staff-access-desktop-light "每一个可以进来的账户，附上第二因素和最后登录时间。")

这份列表背后的规则是[谁能进来](/staff/admin/access-and-roles)。
这一页是您实际按下按钮的地方。

## 看懂这份列表

| 栏 | 内容 |
|---|---|
| 账户 | 在 gftv.asia 的用户名，以及他们在这里的角色。 |
| 本平台 | 能进来或不能进来，已经为您算好。 |
| 第二因素 | 通行密钥、验证器应用、备用码，或只有密码。 |
| 最后登录 | 什么时候，以及用什么证明的。 |

**被拒绝的账户仍然留在列表上。**
这一页是别人来查谁有权限的地方，而「我们三月把它拿掉了」也是那个答案的一部分。

账户旁边的 **在 gftv.asia 未通过审核**，代表第一步就拒绝了他们。
这一页上的任何东西都不会放他们进来。那要在 gftv.asia 修。

第二因素栏里的 **只有密码** 值得留意。
它不是错误，而是一件值得去问那个人的事。

## 三个按钮

![某个账户的权限](pending:admin-access-row-desktop-light "一行上的三种状态，以及原因栏位。")

**允许** 会写下一笔说「是」的覆写。
不论他们在 gftv.asia 的角色怎么说，他们下次来访时都能打开管理后台。

**拒绝** 会写下一笔说「否」的覆写。
他们会立刻失去管理后台，包括已经开着的标签页。他们写过的东西都不受影响。

**交由角色决定** 会删掉那笔覆写。
他们在 gftv.asia 的角色会重新决定，包括那个角色日后变动的情况。

**对话框会告诉您这次更改今天会造成什么。**
如果他们的角色本来就让他们进得来，那么允许现在什么都不改变，但日后仍然有意义。

> [!WARNING]
> 拒绝是立即生效的，而且会传到已经开着的标签页。
> 如果您是在事故处理期间拒绝某人，他们几秒内就会察觉。

## 原因

**拒绝时必须填写。** 另外两个会询问，但不填也接受。

它会留在那一行上，也留在稽核日志里，而且永远不会显示给当事人。
请为一年后读这份列表的人写，并说明是谁要求的。

## 给一个没有角色的人权限

**给某人权限** 会用用户名找到一个 gftv.asia 账户，并为它写下一笔覆写。
两个标记都没有的人就是这样进来的。

**账户是在 gftv.asia 建立的，不在这里。**
在那边没有账户的人无法从这一页加进来，任何搜索都找不到他们。

他们会以 **招聘负责人** 的身份进来，因为他们没有 `is_admin`。
要让某人成为管理员，那是 gftv.asia 上的更改。

## 这一页不会做什么

**这里没有按钮可以重设别人的密码。** 这是刻意的。
员工用自己的恢复码加上第二因素自行设定，
而那同时也会改掉他们的 gftv.asia 密码。

有人卡住而且什么都不剩，请看[当有人无法登录时](/staff/admin/cannot-sign-in)。

**您无法拿掉自己的权限。**
您那一行会标示为您自己，网站会在那一行上同时拒绝「拒绝」和「交由角色决定」。
另一位管理员可以做，这让这个操作仍然可行，同时避免它变成自己搞砸自己。
