# 谁能进来

有两个问题看起来像一个，其实不是。

1. **这个账户到底能不能打开管理后台？**
2. **进来之后，它是招聘负责人还是管理员？**

第一个在这里决定，也就是[员工权限](/staff/admin/staff-access)。
第二个在 gftv.asia 决定，本站只是读取它。

## 规则，分三步

每一次登录都会照这个顺序执行。第一个能给出答案的步骤，就是答案。

1. **`is_approved` 必须为真。**
   在 gftv.asia 上没有通过审核的账户会被拒绝。这里没有任何东西可以豁免这一条。
2. **如果有覆写记录，就由它决定。**
   员工权限写的就是那一笔记录。它在两个方向上都胜过角色。
3. **否则由 `is_admin` 或 `is_editor` 决定。**
   任一标记都会开门，两者都没有也不会把门关上。

> [!NOTE]
> 覆写是本站自己数据库里的一笔记录，那些标记则在 gftv.asia。
> 正因为它们是两份记录，其中一份才可能胜过另一份。

**覆写有三种状态，而第三种不是一个值。**

| 状态 | 那笔记录说什么 |
|---|---|
| 允许 | 在这里允许，不论角色怎么说 |
| 拒绝 | 在这里拒绝，不论角色怎么说 |
| 交由角色决定 | 由 gftv.asia 的角色决定 |

**交由角色决定代表根本没有那笔记录。**
把决定交还回去就是删掉它。
这在一年后很重要：那个账户会再次跟随它在 gftv.asia 的角色，包括角色变动的情况。

## 两种角色

侧边栏顶部的标签会说明一个账户持有哪一种。

| 角色 | 能打开什么 |
|---|---|
| 管理员 | 打开这里的一切，以及管理员指南和开发说明文件 |
| 招聘负责人 | 打开职位和申请，以及招聘负责人指南 |

**`is_admin` 就是管理员。其他任何有权限的都是招聘负责人。**
这涵盖 `is_editor`，也涵盖靠覆写放进来、两个标记都没有的账户。
一个被授予权限却什么都看不到的人，会以为授权失败了。

## 每个角色在本站能打开什么

这些指南跑在第二个网站上，用同样的账户和同样的登录方式。
有四个层级决定读者能打开什么，而每一个层级都包含它上面的那些。

| 层级 | 谁读得到 |
|---|---|
| public | 任何人，包括没有登录的。 |
| poster | 有权限、而且没有 `is_admin` 的员工。 |
| admin | 有 `is_admin` 的员工。 |
| developer | 和 admin 是同一批账户。 |

**没有单独的 developer 标记，也不要去发明一个。**
管理员就是这个项目的开发者，所以最后两个层级是同一批人。
把层级分开，是因为那些页面服务于不同的工作。

**读者永远不会被告知自己是「开发者」。**
显示给他们的是管理员或招聘负责人，那才是他们的账户对他们的实际说法。

## 本站不能更改什么

- **账户。** 它们在 gftv.asia 建立。
- **密码。** 员工自行设定。这里刻意没有任何按钮可以设定别人的密码。
- **admin 和 editor 标记。** 在这里读取，在那边写入。

它能更改的是那一笔覆写记录。请看[管理员工权限](/staff/admin/staff-access)。
