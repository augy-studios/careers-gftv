# 当有人无法登录时

**两个体系，而它们不是同一个问题。**
申请人账户属于本站。员工账户属于 gftv.asia，本站只是读取它。

在做任何事之前，先弄清楚别人问的是哪一个。

> [!WARNING]
> 每一次都请先用别的方式确认您在跟谁说话。
> 这一页上的每一个操作，都是把一个账户交到某人手上。

## 申请人

**他们自己能做什么。**
一个账户恢复码就能设定新密码。
如果账户设有通行密钥，也会一并要求验证。

**本站没有电邮**，所以没有重设链接，他们也没有别的自行回来的路。

**恢复码用完之后，没有人能让他们自行回去。**
那正是他们被告知要联系团队的时刻，也是这一页存在的原因。

您能做什么，在[申请人账户](/staff/admin/applicant-accounts)里：

| 他们的问题 | 该怎么办 |
|---|---|
| 忘记密码，有恢复码 | 什么都不用做。他们本来就可以。 |
| 忘记密码，没有恢复码 | 要求重设密码。 |
| 联系不上第二步验证，有备用码 | 什么都不用做。备用码能让他们通过。 |
| 失去了接收恢复码的那个 Telegram 账户 | 解除 Telegram 绑定。 |
| 以上都帮不上 | 设定他们的密码，请先读清楚它的代价。 |

**要求重设密码是应该优先使用的那一个。**
他们在下次登录时自己选一个，没有人会知道它，而记录上仍然显示是他们自己选的。

**设定密码是最后手段。**
一旦您知道了它，日志就再也无法显示某件事是他们做的还是您做的。
这几个操作每一个都必须填写原因。

**被暂停的账户在持有人看来就像密码问题。**
在照着这份表走之前，请先确认登录是不是被暂停了。

## 员工

**他们自行设定密码**，用员工账户恢复码加上他们的第二因素。
设定它同时也会改掉他们的 gftv.asia 密码，因为那是同一个账户。

**这里刻意没有按钮可以替他们重设。**
[员工权限](/staff/admin/staff-access)那一页上就写着这一点。

| 他们的问题 | 在哪里解决 |
|---|---|
| 忘记密码，有恢复码 | 他们自己重设。 |
| 没有恢复码也没有第二步验证 | gftv.asia。这里没有人做得到。 |
| 在 gftv.asia 未通过审核 | gftv.asia。 |
| 登录得进去，管理后台却拒绝他们 | 本管理后台里的员工权限。 |
| 通行密钥在预览站点上不管用 | 这是预期中的。通行密钥绑定在一个地址上。 |

**登录之后被挡下，是那种读起来像密码问题、其实不是的情况。**
一个在 gftv.asia 登录得进去、在这里却被挡下的人，
是权限问题，不是密码问题。请看[谁能进来](/staff/admin/access-and-roles)。

**建立账户和协助重设密码都在 gftv.asia。**
两个体系，一句话：本站从不建立员工账户，也从不设定员工密码。

## 结束之前

**在原因里写清楚您做了什么。**
下一个读那个账户历史记录的人，很可能就是一年后的您，
当同一个人再来问的时候。

**告诉他们有什么变了。**
每一个协助操作都会结束登录状态和受信任的设备，
所以他们在其他设备上会被退出登录，应该让他们有心理准备。
