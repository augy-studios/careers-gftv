# 每日运行

概览上的 **每日维护**。
有一个排程每天跑一次，并在这里汇报，因为没有人盯着它跑。

它做什么写在[概览](/staff/poster/overview)上，招聘负责人也会读那一页。
该怎么处理写在这里。

## 它可能说什么，以及该怎么办

| 它说 | 该怎么办 |
|---|---|
| 全部完成 | 什么都不用做。 |
| 上次运行是几小时前 | 请看下文。每日排程漏跑了一次。 |
| 完成但有错误 | 请看下文，并检查部署日志。 |
| 开始了却从未结束 | 同上。它很可能在中途被停掉了。 |
| 已关闭 | 等原因过去之后，把 `cron` 开关重新打开。 |
| 还没有运行记录 | 如果网站上线已经超过一天，代表排程没有触发。 |
| 无法读取 | 查询失败了。这不是对那次运行的判断。 |

**已关闭是某个人做出的决定。**
`cron` 这个键在[维护开关](/staff/admin/maintenance-switches)页面上。
在它关着的期间，过了截止日期的职位仍然开着，也没有东西清扫过期记录。

**没有触发才是要往上反映的那一个。**
排程是 Vercel 的，不是这个管理后台能控制的东西。
它写在开发说明文件里，而且那是一次代码改动，不是一项设置。

> [!NOTE]
> 那次运行会在它所述时间前后大约一小时内触发。
> 晚几个小时代表排程在运作，晚一天则不是。

## 一次完成的运行会汇报什么

四个数字，每一个都是那次运行中有所改变的项目数量：

- 因为过了截止日期而 **被关闭的职位**。
- **被放弃的、无人回答的申请提示。**
- **被删除的过期记录。**
- **被检查的申请表单**，以及其中有几份目前不可用。

**数值为零不会被当成消息印出来。** 那次运行只说明有什么改变了。

## 当表单检查标记出某则职位时

被标记的职位会列在面板上，附上两种状态之一。

**表单不接受回复。** 表单载入了，但已经关闭作答。

**表单不存在。** 表单不见了。

**两者都代表在那个职位上按申请的人会走进死胡同。**
处理方法在[坏掉的申请表单](/staff/admin/a-broken-form)。

## Telegram 队列

**Telegram 通知** 就在每日运行旁边，而且完全是另一回事。
机器人跑在它自己的服务器上，不在本站。

- **过去一天送出的数量**，那是健康的那一行。
- **等待中，最早的一笔是多久之前的。** 机器人很可能没有在运行。
- **已放弃。** 投递失败次数够多，已经停止尝试。

**机器人停止期间不会有东西丢失。**
队列会保留，重新运行后就会送出。
丢掉的是时效，所以今天被问到问题的人会晚一点才知道。

**被略过的通知** 是那些没有绑定 Telegram 的申请人。
那是他们自己的选择，不是故障。

重启机器人是它那台服务器上的工作。
它写在开发说明文件里，而且不是这个管理后台做得到的事。
