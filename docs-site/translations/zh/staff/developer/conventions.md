# 值得不必重学的惯例

这一页上的每一条，都是曾经做错过一次才学到的。
如果您只读这本指南的一页，就读这一页。

## 技术栈规则

**不用框架，入队平台也不做构建。**
纯 HTML、CSS 和 JavaScript，ES 模块，原样提供。
说明文件网站的构建是唯一被明文说明的例外，
而且它只用 Node 内建的东西，不带任何依赖。

**用内联 SVG，绝不用表情符号**，并以 `currentColor` 上色。
**不用渐层、光球或色块团。**
两者都是主题文件的规则，而且适用于任何人新增的任何东西。

**任何地方都不用长破折号**：文案、注释和说明文件都不用。
请改用逗号、分号、冒号或句号。

**绝不要写死颜色。**
请引用一个符记，否则它在四种主题组合里的三种都会不正确。

## 文案的风格规则

**有一个被禁的词组，而且它适用于每一个读者看得到的英文字符串。**
那包括各个字典、各个页面、阶段列表、`llms.txt`，
以及机器人 Python 里的每一个字符串，连它的简介文字也算。

> [!WARNING]
> **有一个意思是「优先于」的两词词组被禁用了。**
> 运行 `node check-copy.js --list` 就能看到它。
> 那七个替代写法是：instead of、in place of、as opposed to、over、
> in preference to、without，以及 and not。

这条规则对这些页面同样强制执行，
这正是这一页要用描述的方式来指称那个词组的原因。
真正算数的那份规则副本是那个脚本。

源代码注释、各份 README 和那些迁移都不算文案，一律不动。

**读者会遇到的每一样东西，句子上限是 25 个词。**
这个上限是量出来的：它到来的时候，整个入队平台字典里有七个句子超过它。
入队平台自己的平均值不到七个词，所以那个上限不是目标。

**先写出技术名词，再解释它。**
通行密钥、恢复码、双重验证、冷却期：请保留那个词，
因为那就是按钮上和浏览器自己的提示里用的词。
在读者第一次遇到它的地方给它一个平实的解释。
换掉那个名词，会让页面和屏幕说着不一样的话。

`node check-copy.js` 会对九个来源强制执行这一切，
而 `--list` 会印出它读了什么。

## 四个检查器

没有一个需要凭据、数据库或网络。**推送之前请跑它们。**

| 命令 | 它抓到什么 |
|---|---|
| `node check-i18n.js` | 一个会在画面上渲染成自己名字的键。 |
| `node check-copy.js` | 被禁的词组、过长的句子，以及华文用词规则。 |
| `node check-precache.js` | 一个不在磁盘上的预先缓存条目，两个网站都检查。 |
| `node gen-docs-lib.js --check` | 一次只落在共用模块其中一份副本上的改动。 |

说明文件部署之前还有两个：
`node docs-site/scripts/build.js`，它同时也就是那次部署，
以及 `node docs-site/scripts/embed-tests.mjs --check
docs-site/api/_content/developer/test-scripts.json`。

还有 `node gen-review.js`，
它会在遇到任何一个带汉字、却不在它两份名单上的文件时失败。

## 那些会默默失败的东西

下面每一条在这本指南里都有一页，
而它们之所以在这里，是因为在有人回报某件怪事之前，那些失败都是看不见的。

- **一个没有被提升的 `VERSION`。**
  回访的读者会继续拿到旧构建。
  请看[服务工作线程](/staff/developer/the-service-worker)。
- **一份没有被重新生成的副本。**
  一个修正落在其中一个网站上而不在另一个上，两者相隔数月。
  请看 [Vercel](/staff/developer/vercel)。
- **一条只在本地检查过的重写规则。**
  在平台上文件系统会胜过重写规则，在本地则不会。
- **一个不再被设定的 `lang` 属性。**
  华文会以日文字形渲染，而其他东西看起来都没问题。
- **一条规则的第二份副本。**
  工作线程里的队列判定、绘制前的主题常量，
  以及机器人的层级逻辑，每一个都是刻意留下的第二份副本。
  每一个都有一项检查，它唯一的工作就是抓住这一对漂移。

## 被核对的副本

**没有东西去比对的副本，就是会变陈旧的那一份。**
凡是这次构建无法避免要写两次的地方，第二份副本都由一个脚本去比对：

| 那份副本 | 由什么去比对 |
|---|---|
| 机器人的指令列表，出现在三份文件里 | `python commands.py --check` |
| Apps Script 的那些步骤，出现在管理后台和一本指南里 | `phase14-test.mjs --only=guide` |
| 权限规则，出现在两个模块和一本指南里 | `phase14-test.mjs --only=admin-guide` |
| 每一个共用模块，在两个网站上 | `gen-docs-lib.js --check` |
| `tests/` 里的每一个脚本，出现在这本指南里 | `embed-tests.mjs --check` |

**最好是根本没有第二份副本。**
它们之所以存在，是因为另一种做法更糟，而每一个的理由都写在它旁边。

## 没有任何东西写死阶段编号

**一个文件决定什么已上线**，其他一切都读它。
那条规则刚好被破坏过一次，
是一个测试文件列出了哪些功能还没做好。
结果有三项检查把一个已经往前走了的构建报成缺陷。

**一个测试去指名哪些功能还没做好，就是同一个错误换了顶帽子。**
请从页面上读取状态，并在没有东西可检查时用一句话跳过。

## 提出选项，而不是自己决定

**凡是规格书和其他任何东西不一致的地方，都要问。**
说明书在第七行就写了这一点。

请提出具体的选项、用一行说明您会选哪一个以及为什么，
然后让拥有这个项目的人来挑。
不要写一个开放式的问题然后等着。

**正是那个习惯，让工作备忘日后读得回来。**
里面每一个决定旁边都写着被否决的替代方案。
那是唯一能让一个决定在一年之后仍然可被审阅的东西。

## 三个属于工作本身的习惯

**在同一次改动里更新 README。**
README 在它不再和代码相符的那一刻就陈旧了。
一份陈旧的比没有更糟，因为读它的人会用读最新版一样的信任去读它。

**边做边写备忘条目。**
`next-steps.md` 在每一个阶段的开始和结束都会重写一次，
而一条事后才补上的偏离，是一条只记得一半的偏离。
请看[工作备忘](/staff/developer/the-working-memo)。

**编辑页面时，请一并检查它的翻译。**
每一个说明文件页面在 `docs-site/translations/` 底下都有一份华文文件，
而编辑英文不会动到它。
一个英文动了、华文没动的页面，会对两种读者说不一样的话。
**没有任何东西会告诉您**：那份翻译仍然标示为就绪，也仍然照常提供。

这是刻意的。第 9 部分交付时曾提出自动侦测，但没有被采纳。
一个会因为一个错字就失败、直到有人重新翻译那一页才肯放行的构建，
是大家最后学会绕过去的构建。
所以这是一个习惯而不是一项检查，和它上面那两个属于同一类。

`node gen-review.js` 会把每一页和它的英文逐段并排，
那是看出什么变动了最快的方法。
