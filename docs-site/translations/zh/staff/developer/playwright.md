# Playwright

**本站的每一张截图都是用 Playwright 拍的，绝不是手动拍的。**
下面这些规则是 16g 的，而且不会改变。

Playwright 是根目录 `package.json` 的开发依赖，
这正是用到它的那些脚本住在那一层的原因。
本站的截图脚本住在 `docs-site/scripts/` 里，
配置的作用范围限定在 `docs-site`，所以它绝不会变成入队平台的依赖。

```sh
npm install
npx playwright install chromium
```

## 不会改变的那些规则

- **按需运行，针对本地或已写入种子数据的实例。**
  绝不作为 Vercel 构建的一部分，也绝不针对生产环境。
  反正 Vercel 在构建时跑不了浏览器，而生产环境里有真实的申请人数据。
- **每一张截图显示的都是虚构的人在申请虚构的职位**，来自种子脚本。
  绝不会出现任何真实的申请人、电邮或 Telegram 帐号。
- **绝不拍摄实时的恢复码、备用码、登录验证码、绑定令牌或 Google 表单网址。**
  如果某一页需要图示其中一样，请写入一个假值，并在图说里说明那是示例。
- **每次运行都是确定性的。**
  停用动画、冻结或遮蔽相对日期，
  并遮蔽任何在两次运行之间会变的东西。
  一套每次拍摄都会产生差异的截图，就不再是可审阅的了。
- **桌面和手机，浅色和深色**，
  好让指南能展示汉堡菜单和窄屏版面。

## 一张截图放在哪里，以及构建为什么强制这一点

| 页面 | 文件 | 写法 |
|---|---|---|
| 公开 | `docs-site/public/screenshots/` | 绝对路径，`/screenshots/name.webp` |
| 受闸门保护 | 在 `api/_content/<section>/` 里页面旁边 | 一个光秃秃的文件名 |

**受闸门保护的页面，它的图片会走页面本身走过的同一条已验证路由。**
一个带着公开截图的受闸门页面，是多绕了几步的泄漏，
所以两个方向都是构建失败。
`content/` 里的一张图片会让构建停下来，
一个指向公开图片的受闸门页面也一样。

**资源是在它所属区块的层级受闸门保护的。**
一个 `.png` 里没有地方可以放 `access` 键。
读者必须先通过那个区块，才会被告知那张图片存在。

**不用 SVG。**
SVG 是一份可以携带脚本的文件，而且从本站的来源提供，
但受闸门资源要的就是一张截图。
提供的类型是 `.webp`、`.png`、`.jpg`、`.jpeg` 和 `.gif`。

## 那份清单

截图运行是由一份清单驱动的，绝不是由参数驱动，
这样接手的人才能重现同一张截图。
每一个条目都写明页面路径、视窗大小、主题和模式，以及要等待的元素。
它也写明层级、要遮蔽的区域，以及这次拍的是整页还是某一个选择器。

**新增一张截图，就是清单里的一个条目加上页面上的一个位置。**
重跑一张，就是只为那一个条目运行截图。

## 待补的位置

在截图存在之前，页面会带着一个占位符，
它读起来是待补，而不是坏掉：

```text
![The overview](pending:admin-overview-desktop-light "The dashboard overview.")
```

它会带着真实截图将来会有的替代文字和图说渲染出来。
**那个名字就是它将来会被赋予的文件名**，由清单条目构建出来，
所以一个位置和它未来的截图不可能对不上。

> [!TIP]
> 位置名称里的一个错字，就是一张没有人会去拍的截图。
> 第 14 阶段的检查会把指南里的位置名称和命名形状对照，并在重复时失败。

## 写入种子数据，以及它的代价

代码库根目录的 `node seed.mjs` 会写入示例职位和两个示例账户。
一个读英文，一个读新加坡华文，好让华文页面能在登录状态下被拍摄。
它会把那两个密码印出来一次。

```sh
node seed.mjs                 # says what it would do, and writes nothing
node seed.mjs --yes           # does it
node seed.mjs --clear --yes   # removes it, and the phase 3 dev seed with it
```

> [!WARNING]
> **在入队平台对搜索引擎开放期间，它会拒绝写入**，
> 而它从第 12 阶段第 8 部分起就一直是开放的。
> 所以一次截图运行必然是一次刻意的 `--anyway`，
> 并在截图拍完之后立刻清除。

**每一个部署背后都是同一个数据库**，所以针对预览部署拍摄并不能避开这一点。
网站地图在边缘节点缓存一小时。
在那一小时内写入又清除的示例职位，仍然可能已经被交给某个爬虫。
唯一在任何人控制之内的是那个时间窗口，所以请让它短一点。

**清除种子数据会让两个不是截图的文件失效。**
入队平台 `manifest.json` 里那两张安装截图是 `/search` 的真实拍摄，
所以之后要跑 `node gen-screenshots.js`。

## 其他几个截图脚本

`tests/` 里有三个脚本用 Playwright 产生图片，它们不属于这条流水线。
它们在[测试脚本](/staff/developer/the-test-scripts)那一页有说明，
您也可以从那里下载每一个。

| 脚本 | 它产出什么 |
|---|---|
| `capture-themes.mjs` | 二十张图片，五个界面上的四种主题组合。 |
| `screenshot.mjs` | 单一宽度下的管理后台，用工作树的 CSS 取代部署上的那一份。 |
| `layout-check.mjs` | 窄宽度的版面检查，验证那条「表格可以在自己的框里滚动，页面主体不可以」的规则。 |

**`capture-themes.mjs` 不是一项检查，它永远不会通过或失败。**
它产出图片给人看，而那个人才是检查。
它之所以存在，是因为对比度是算术，
而算术无法告诉您一个通过了 AA 的符记看起来不对劲。
