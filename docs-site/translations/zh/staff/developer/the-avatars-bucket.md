# 头像储存桶

**每个申请人账户一张方形图片，此外什么都没有。**
`main-site/AVATARS.md` 是那份指南，
这里描述它，好让读者不必再开第二个标签页去了解它的形状。

**它刻意改变了一个已定案的决定。**
规格书第 10 节第 1 项写着：不使用 Supabase Storage，不允许上传。
那句话是针对申请写的，而不论如何，申请和履历都留在 Google 表单里。
头像是被记录下来的例外，也是唯一的例外。

## 决定了这一切形状的那个限制

**浏览器绝不会收到 anon 密钥**，
所以前端根本没有 Supabase 客户端。
那就排除了常见的做法，也就是浏览器直接上传到 Storage，
再由 `storage.objects` 上的策略决定谁可以写入。

所以那些字节要经过一个函数：

```text
browser                       Vercel function              Supabase Storage
  resize, crop, encode WebP
  POST image/webp        -->  check magic bytes, size
                              upload with the service key  -->
                              write gftvjobs_users.avatar_url
  { avatar_url }         <--
```

有两个后果，而两者都决定了这个设计：

- **Vercel 函数的请求体最多 4.5 MB。**
  在浏览器里压缩是让上传成为可能的原因，不是锦上添花。
- **`readJson` 把请求体上限设在 64 KB**，
  那对 JSON 是对的，对图片则远远太小。
  `api/account/avatar.js` 用它自己的上限去读原始请求体。
  不要把那个默认值在全局调高。

## 那个储存桶

**没有任何迁移会建立它。**
它必须先存在，那个端点才会运作，SQL 在 `AVATARS.md` 的第 1 节里。

| 栏位 | 值 |
|---|---|
| 名称 | `gftvjobs-avatars` |
| 公开 | 是 |
| 文件大小上限 | 256 KB |
| 允许的类型 | 只有 `image/webp` |
| `storage.objects` 上的策略 | 没有 |

**没有图片的账户会改为渲染它的首字母**，
那是常态，不是失败。
所以在有人尝试之前，一个不存在的储存桶看起来和没有人上传过完全一样。

## 那三个文件

| 文件 | 它做什么 |
|---|---|
| `assets/js/avatar.js` | 在浏览器里做方形裁切、缩放和 WebP 编码。 |
| `api/account/avatar.js` | 接收字节，POST 用于设定，DELETE 用于移除。 |
| `api/_lib/avatars.js` | Storage 那一半：储存桶、魔术字节检查，以及上传顺序。 |

## 那些原本会被忘掉的事

**删除账户时必须一并删除它的对象。**
危险区会级联删除申请人的各笔记录，而 Storage 不属于那个级联。
一个账户的所有东西都在 `{user_id}/` 底下。

**路径每次上传都带一个随机成分**，所以缓存会自行更新。
一个和登录状态上那个不同的 URL，代表图片已经换过了。

**旧的对象是在新的 URL 存好之后才删除的，绝不会在之前。**
两者之间失败会留下一个孤儿文件，那很便宜；
反过来的顺序则会让一个账户指向不存在的东西。

**服务器上不做图像处理。**
那个端点只做一次长度检查和十二个字节的魔术数字检查。
不要为了浏览器已经提供的便利，往请求路径里加一个解码器。

**被停用的账户，它的图片在自己的 URL 上仍然读得到**，因为那个储存桶是公开的。
那是这个储存桶做的取舍。
要改变它，意味着改用私有储存桶，并为每一次显示签发一个签名 URL，包括管理后台的。

## 离线，以及服务工作线程为什么完全不碰它

**申请人自己的头像会以 blob 形式保存在 IndexedDB 里**，以他们的用户编号为键。
退出登录时它会和他们其余的数据一起被清掉。

**服务工作线程绝不缓存 Storage 的 URL**，
而且它根本不拦截跨源请求。
原因在于管理后台：它会渲染别人的面孔，
而一条「用到就缓存」的规则无法把那些和读者自己的区分开。

> [!TIP]
> 那个占位图仍然是必要的，也仍然重要。
> 任何没有登录的人、任何在首次载入前就离线的人，
> 以及管理后台里的每一个头像，都会回退到它。
> 所以它必须搭配显示名称作为 `alt` 时读起来是正确的。
