# 测试脚本

**这里没有持续集成套件，也没有测试数据库。**
有的是：`tests/` 里的 Playwright 脚本，
手动针对某个部署运行，每个阶段一个文件，另外还有几个小工具。

`tests/README.md` 才是关于运行它们的完整说明。
这一页是入门介绍和下载。

> [!DANGER]
> **这些脚本针对真实网站运行，并写入真实记录。**
> 这里没有夹具数据库，也没有测试模式。
> 一次运行会以一个真实的员工账户登录、建立真实的职位、
> 提出真实的待办事项，并在退出时删除它建立的东西。
> 第一次运行之前请先读 `tests/README.md`。

## 第一次运行之前

您需要三样东西。

1. **Node 20 或更新，以及 Playwright 的 Chromium。** 从代码库根目录：

   ```sh
   npm install
   npx playwright install chromium
   ```

2. **一个有入队平台权限的员工账户。**
   那道守卫在每一次请求都会重新读取登录状态并重新检查权限规则，
   所以没有办法伪造一个。
   每一个阶段文件都要以管理员跑一次，再以招聘负责人跑一次：
   账户的角色决定好几个区块里跑的是哪一半。

3. **一个可以指向的地方。**
   默认是生产环境，因为通常没有预览部署。
   **有预览部署时请指向预览部署**，用 `BASE=`。

```sh
STAFF_USER=yourname STAFF_PASS='...' node tests/phase7-test.mjs
STAFF_USER=yourname STAFF_PASS='...' node tests/phase7-test.mjs --only=editor
```

**每一个文件都接受 `--only=`**，后面写一个或多个区块名称。
这就是您重跑刚改过的那一部分、而不是花半小时跑完全部的方式。

## 哪些不需要凭据

有四样东西只针对工作树运行，它们也是推送前该跑的那几个。

| 命令 | 它证明什么 |
|---|---|
| `node tests/phase10-test.mjs` | 入队平台的服务工作线程，在真实浏览器里，离线状态下。 |
| `node tests/phase12-test.mjs --only=responsive,landscape,a11y,a11y-keyboard` | 每一种宽度下的版面和无障碍。 |
| `node tests/phase13-test.mjs --only=live` | 说明文件网站的部署会怎么回答一个陌生人。 |
| `node tests/phase14-test.mjs` | 两个网站的外观，以及本站的工作线程。 |

**`PATCH_ASSETS=1` 会提供工作树的样式表、脚本和页面**，
取代部署上的那些，好让一个修正在推送之前就能被证明。

## 一次干净的运行不等于完整覆盖

任何需要 SQL、第二个员工账户、一次重新部署、
一份真实表单，或一个坐在键盘前的人的东西，
都会 **被跳过，绝不会默默算成通过**。
最后的计数会说明跳过了多少，而每一次跳过都会印出它做不到什么。

**机器人完全没有这一套。**
`tests/phase11-test.mjs` 是那个阶段的网站那一半，此外什么都没有。
VPS 上的 Python 是由一个人照着 `telegram-bot/README.md` 里的检查清单走过来检查的，
那是一个决定，不是一个疏漏。

## 一次运行会写下什么，以及事后怎么清理

阶段文件建立的每一样东西都有前缀，并在退出时删除。
每小时删除十笔的预算够不到的部分，会被下架并列出来，好让人事后移除。

```sh
STAFF_USER=... STAFF_PASS='...' node tests/cleanup-smoke.mjs --dry-run
STAFF_USER=... STAFF_PASS='...' node tests/cleanup-smoke.mjs
```

**`create-applicant.mjs` 会建立好几个区块需要的那个申请人账户**，
并给它一些东西，让它能成为一份列表。
一个空的管理后台会通过世上每一条无障碍规则，
这正是那个账户要带着历史记录写入的原因。

## 三个调试脚本

`debug-prompt.mjs`、`debug-register.mjs` 和 `debug-slug.mjs`
各自都是重现某一个特定失败的最短路径。
**留着它们，与其说是为了那些缺陷，不如说是为了那个形状**：
一个新的调试脚本，会从最接近的那一个复制过来开始。

## 那些脚本

`tests/` 里的每一个文件，附上它自己的描述和运行它的命令，
取自该文件开头的那段注释。
**这里没有任何东西是手写的**：
`docs-site/scripts/embed-tests.mjs` 会读取那个目录，
而 `--check` 会在这张表过时的时候失败。

> [!NOTE]
> **这个下载没有自己的地址。**
> 那个文件随这一页一起传送，
> 而您浏览器保存的那条链接是在这个标签页里建构出来的，也随它一起消亡。
> `tests/` 里没有任何东西是机密，也没有任何东西持有凭据：
> 每一个脚本都从环境变量取得那些。
> 如果哪一天有一个脚本需要持有不能被读取的东西，那它就不属于 `tests/`。

**在把一个脚本拿去对着实时数据库运行之前，请先读它。**
正文就在这一页里，所以那不花什么成本。
