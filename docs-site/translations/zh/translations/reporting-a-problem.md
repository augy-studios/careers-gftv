# 回报问题

每则职位靠近底部的地方都有 **回报翻译问题**，就在分享和返回链接旁边。
它刻意做得安静。不会弹出任何东西，也不会问您这个翻译好不好。

同样的控件也出现在其他大段显示译文的地方，以及界面本身上。
导航栏里一个不好的标签也值得回报。
您不该需要自己去分辨那是界面文字还是职位的一部分。

## 它会问什么

- **哪个版本有问题。** 预设是您正在阅读的语言。
- **哪一部分。** 预设是整则职位。
  您可以缩小到标题、摘要、职位描述、您会做什么、需要您具备什么、加分项，或地点。
- **哪里不对。** 一两句话。这一项是必填的。
- **更好的写法，如果您有的话。** 选填，没有人期待您提供。

## 用您习惯的语言写就好

回报可以用任一种语言写。
您不会被逼着用您正在回报的那个语言，而那往往是您读得最不好的那一个。

## 建议绝不会自行套用

表单上就写着，这里值得再说一次：

> 选填。在任何改动之前，都会有管理员先读过。

您按下送出时，您的写法不会出现在网站上。每一次都有人先读过。

## 您需要一个账户

回报需要您先登录，好让团队可以就此回复您。

如果您没有登录，控件会打开和申请相同的登录提示，
并在您回来之后完成回报。您打的内容不会遗失。

## 送出之后会怎样

> 谢谢。团队成员会看这一则。

我们不承诺日期，因为承诺日期等于凭空编造。

**每一份回报都会得到答复，包括不采纳的。**
管理员在结案时必须写下说明，不论他们的决定是什么。
默默结案只会教您下次不必费心。

## 查看您回报过的内容

您的回报列在账户设置页面的 **您回报过的翻译问题** 底下。
每一份都会显示您提出的时间和目前的进度：

- **等待阅读**
- **处理中**
- **维持原样**
- **已修正**

处理完之后，团队的决定会显示在旁边。

## 它不是待办事项

回报绝不会出现在您的[待办事项](/portal/outstanding-tasks)页面上，
也绝不会加到页首的数字里。

那一页是给团队需要您处理的事情用的，而回报的方向正好相反。
如果管理员需要就此追问您，他们会提出一个普通的问题，那个才会落在待办事项页面上。
